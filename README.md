# Python API Demo: Flask vs. FastAPI

A side-by-side demonstration of the exact same minimal web API built in two popular Python frameworks: **Flask** (`app.py`) and **FastAPI** (`fastapi_app.py`).

## Setup (using [uv](https://docs.astral.sh/uv/))

Install all project dependencies:
```bash
uv sync
```

## Running the Applications

### Option 1: Run the Flask App (`app.py`)
```bash
uv run app.py
```
- Web UI: http://localhost:5000

### Option 2: Run the FastAPI App (`fastapi_app.py`)
```bash
uv run fastapi_app.py
```
- Web UI: http://localhost:8000
- Interactive Swagger UI Docs (auto-generated by FastAPI): http://localhost:8000/docs

---

## Endpoints

Both apps expose the same two endpoints:

- **`GET /`** — Serves the demo web page (`templates/index.html`) where you can interactively test the API.
- **`POST /api/greet`** — Accepts a JSON payload (e.g. `{"name": "Alice"}`) and returns a JSON greeting.

Example `curl` request (adjust port `5000` for Flask or `8000` for FastAPI):
```bash
curl -X POST http://localhost:5000/api/greet \
  -H "Content-Type: application/json" \
  -d '{"name": "Alice"}'
```

## Flask vs. FastAPI: Key Differences

1. **Request Parsing & Validation**
   - **Flask**: You manually read the request body with `request.get_json()` and validate fields yourself.
   - **FastAPI**: You define a Python class (`GreetRequest`) using Pydantic type hints. FastAPI automatically parses, validates, and returns clear error messages if the input doesn't match the expected types.

2. **Response Serialization**
   - **Flask**: Uses `jsonify(...)` (or returns a dict) along with an explicit status code.
   - **FastAPI**: Directly serializes Python dictionaries and Pydantic models into JSON with high performance.

3. **API Documentation**
   - **Flask**: Does not include built-in interactive documentation out of the box (requires extensions like `flask-smorest` or `flasgger`).
   - **FastAPI**: Automatically generates OpenAPI schemas and interactive Swagger UI (`/docs`) and ReDoc (`/redoc`) pages from your Python type hints.

4. **Execution Model (WSGI vs. ASGI)**
   - **Flask**: Built on WSGI (synchronous by default). Includes a built-in development server (`app.run()`).
   - **FastAPI**: Built on ASGI (asynchronous `async`/`await` first) and runs on an ASGI server like `uvicorn`.

## Pros and Cons

### Flask (`app.py`)
**Pros:**
- Extremely simple, minimal boilerplate, and easy for beginners to grasp immediately.
- Mature ecosystem with decades of tutorials, extensions, and community answers.
- Great for traditional server-rendered HTML websites (Jinja2 templates are built right in).

**Cons:**
- No built-in data validation or request schema enforcement.
- No automatic API documentation (OpenAPI/Swagger) without third-party plugins.
- Synchronous by default (less suited to high-concurrency async workloads).

### FastAPI (`fastapi_app.py`)
**Pros:**
- Automatic request validation and serialization via Python type hints and Pydantic.
- Free, interactive API documentation (`/docs`) generated automatically from your code.
- Native `async`/`await` support and very high performance.

**Cons:**
- Slightly more concepts to learn upfront (Pydantic models, type annotations, `uvicorn` ASGI server).
- Template rendering requires slightly more setup (`Jinja2Templates`) compared to Flask's `render_template`.
